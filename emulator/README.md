# ABN6502 r2 browser emulator

Static, browser-only emulator for Anders Nielsen's ABN6502 r2. Open `site/` with a static HTTP server (`npm run serve`), then visit `http://localhost:8066/`. `npm test` checks a real-ROM boot and keyboard path; `npm run build` verifies firmware checksums and builds `dist/` with a source ZIP.

The CPU is an NMOS 6502 core shared with the [65uino emulator](https://www.imania.dk/65uino-emulator/). The board maps RAM at `$0000–$5FFF`, a minimal 6522 VIA at `$6000–$600F`, video control at `$7000`, and the 32 KiB ROM at `$8000–$FFFF`. The built-in firmware expects its video-memory jumper to place VRAM at `$0800`. VGA is rendered from the 64×32 character grid and the genuine 2 KiB character ROM as a 512×256 monochrome-green image. The ROM's display window is narrower than that full grid. The 6522 Timer 1 and IRQ path are modeled; the RF transceiver is absent, matching an unpopulated board.

Browser keyboard events are translated to PS/2 set-2 scan codes and inserted at the ROM's scan-code staging buffer, where the original firmware handles character translation. The electrical PS/2/6522 shift-register timing is **not** modeled. This high-level bridge supports ordinary typing and ROM shortcut keys but is not a cycle-exact PS/2 interface. The VIA model likewise covers the registers used by the stock boot ROM, not every 6522 mode. Clock rate defaults to the board’s 2 MHz. Tapping the VGA focuses a real transparent text input over the display, so phone soft keyboards can open and send characters through the same ROM parser.

The fullscreen button uses the browser Fullscreen API where it works. iOS Safari and browsers that reject it use an in-page viewport-filling fallback, which cannot remove Safari's browser chrome. In portrait phone fullscreen, the active ROM text region is zoomed by default; **Show full VGA** displays the entire frame. The on-screen **Esc to ROM** button is available because browsers reserve Escape to exit native fullscreen.

The in-screen key drawer provides F1–F12, arrows, Page Up/Down, Home, Enter, Backspace and Esc in normal and fullscreen views. On touch screens it opens by default in portrait and collapses when the VGA text input is focused to leave room for the phone keyboard. Holding an arrow or Page key repeats. In the stock ROM, F1 enters the memory monitor. The first page starts at `$0000` and shows zeroes because reset clears RAM and the first active zero-page variables are near `$00E0`; pressing Page Down once starts at `$00D8` and reveals them. The monitor uses Up/Down for 8-byte steps and Page Up/Down for screen steps; Esc exits.

F4 enters the bundled OSI 6502 BASIC ROM. Its startup asks `MEMORY SIZE?` and `TERMINAL WIDTH?`; Enter accepts each default. The **BASIC programs** drawer includes a one-click F4/defaults shortcut, three editable real-ROM-verified listings (hello/counting, number parade, and a two-choice cave-or-castle game), and a paced text sender for pasted programs. The sender normalizes line endings, checks supported keyboard characters and verifies short lines on the VGA before committing them with Enter. `NEW` in each sample clears any earlier BASIC program; `RUN` starts it. Pasting on the VGA or alternative phone input moves the text into the editor for review rather than dumping a whole clipboard into the small ROM keyboard buffer. Starting BASIC again clears the program in memory. Two limits come from the bundled ROM build itself and would occur on hardware running the same image: (1) the ROM's 128-byte keyboard buffer pointer only resets on F4, so after roughly 128 typed characters in one BASIC session input overwrites ROM variables and can corrupt entered lines; (2) in this build Microsoft BASIC's `FRM_STACK2` "not on page boundary" bug is hit, so binary arithmetic and comparison operators (and `ON…GOTO` lines corrupted by (1)) fail. The included examples avoid those paths, and a listing beginning with `NEW` restarts BASIC first to get a fresh keyboard buffer.

Select a 32 KiB ROM from the file picker to run a different image locally; the file is read by the browser File API and not uploaded. The CPU reset clears emulated RAM. Reload the page to restore the bundled ROM.
